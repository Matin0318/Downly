# انتشار Downly

همهٔ موارد زیر از قبل در مخزن آماده شده است. فقط مرحله‌هایی که با **شما** مشخص شده‌اند را باید خودتان انجام دهید.

## تنظیم یک‌باره
1. **شما:** کلید امضا را بسازید و یک نسخه از آن را جای امنی نگه دارید. اگر کلید را گم کنید، دیگر هرگز نمی‌توانید برنامه را برای کسانی که نصبش کرده‌اند به‌روز کنید:
   ```
   keytool -genkeypair -v -keystore downly.jks -alias downly -keyalg RSA -keysize 4096 -validity 10000
   ```
2. **شما:** در گیت‌هاب به Settings > Secrets and variables > Actions بروید و چهار secret اضافه کنید: `DOWNLY_KEYSTORE_BASE64` (خروجی `base64 -w0 downly.jks`)، `DOWNLY_KEYSTORE_PASSWORD`، `DOWNLY_KEY_ALIAS` و `DOWNLY_KEY_PASSWORD`.
3. **شما:** برای ساخت APK امضاشده روی کامپیوتر خودتان، فایل `keystore.properties` را در ریشهٔ پروژه بسازید. گیت آن را نادیده می‌گیرد:
   ```
   storeFile=downly.jks
   storePassword=...
   keyAlias=downly
   keyPassword=...
   ```
4. **شما (پیشنهادی):** در Settings > Code security مخزن، گزارش خصوصی آسیب‌پذیری را فعال کنید تا [SECURITY.fa.md](../SECURITY.fa.md) همان‌طور که نوشته شده کار کند.

## نخستین انتشار (۱.۰.۰)
فایل `androidApp/build.gradle.kts` از قبل روی `versionCode = 1` و `versionName = "1.0.0"` تنظیم شده است.
1. **شما:** فهرست [TESTING.fa.md](TESTING.fa.md) را روی یک گوشی واقعی و با نسخهٔ **release** اجرا کنید.
2. **شما:** تگ بزنید و push کنید:
   ```
   git tag v1.0.0
   git push --tags
   ```
3. workflow به نام `Release` تست‌های واحد را اجرا می‌کند، APK امضاشده را می‌سازد، SHA-256 آن را می‌نویسد و هر دو را همراه با یادداشت انتشار خودکار در صفحهٔ Releases منتشر می‌کند.

## انتشارهای بعدی
1. `versionCode` و `versionName` را در `androidApp/build.gradle.kts` بالا ببرید.
2. یک بخش به [CHANGELOG.md](../CHANGELOG.md) و [CHANGELOG.fa.md](../CHANGELOG.fa.md) اضافه کنید.
3. تگ بزنید، مثلاً `v1.1.0`.

تگی که `-` داشته باشد، مثل `v1.1.0-rc.1`، به‌صورت *پیش‌انتشار* (pre-release) گیت‌هاب منتشر می‌شود.

## یکپارچه‌سازی پیوسته (CI)
فایل `ci.yml` روی هر push و pull request اجرا می‌شود. تست‌های واحد را اجرا می‌کند، نسخهٔ release بدون امضا را می‌سازد (تا مشکل‌های R8 زود پیدا شوند) و APK دیباگ را هم می‌سازد و به‌عنوان artifact بارگذاری می‌کند. اگر چیزی در دیباگ کار می‌کند ولی در release نه، قوانین keep را به `androidApp/proguard-rules.pro` اضافه کنید.

## نکاتی برای صفحهٔ انتشار
این محدودیت‌ها را بنویسید تا کسی غافلگیر نشود:
- «دسترسی به همهٔ فایل‌ها» و آلارم دقیق بهترین تجربه را می‌دهند. گوگل‌پلی هر دو را محدود کرده، پس این برنامه برای انتشار در GitHub و فروشگاه‌هایی مثل F-Droid در نظر گرفته شده است.
- تورنت‌ها با پایان دانلود متوقف می‌شوند (بدون seed) و محدودیت سرعت روی آن‌ها اعمال نمی‌شود.
- DASH فقط برای پخش‌های آماده کار می‌کند و DRM را پشتیبانی نمی‌کند. صدا و تصویر با `MediaMuxer` خود گوشی به هم وصل می‌شوند.
- فایلی که سرورش حجم را اعلام نکند قابل دانلود نیست.
